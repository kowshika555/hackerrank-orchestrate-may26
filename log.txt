[Turn 4] Escalation rule design
Initial attempt used broad patterns like r"(security|vulnerability|exploit|zero.?day|cve|hack)"
Bug found: "HackerRank" matched the "hack" part, causing false escalations
Fix: Use word-boundary anchors \b and more specific patterns
- "HackerRank" no longer triggers security escalation
- "security vulnerability" correctly escalates
- French pattern r"afficher.{0,50}règles.{0,30}interne" catches mixed-language requests

[Turn 5] Coverage threshold tuning
Initial threshold: 5% token overlap → too aggressive, rejecting valid tickets
Fixed to: 3% token overlap → better balance
Added: company-source keyword length filter (≥4 chars) to reduce noise

[Turn 6] Out-of-scope detection fix
"General Knowledge" ticket: "What is the name of the president of the United States?"
Pattern needed: r"\bpresident\b.{0,40}(which|who|name|of the|states)"
Previous pattern was too narrow.

[Turn 7] Request type classification
